# 测试

本文按源码包与被测对象组织。当前共有 **190 条 JVM 用例**（`app/src/test` 185 条，`app/src/testDebug` 5 条）和 **39 条 instrumented 用例**（`app/src/androidTest`），合计 229 条。

## 一、测试基线

1. JVM 用例使用 JUnit4（`org.junit.Assert`）与 `runTest`；Room 相关用例使用 Robolectric（`@Config(sdk = [35], application = Application::class)`）和内存数据库。
2. Instrumented 用例使用 `AndroidJUnit4`、设备上的真实 SQLite 与 `runBlocking`；Compose 用例使用 `createComposeRule` 或 `createAndroidComposeRule`。
3. 时间基线为 `2026-10`（`[2026-10-01, 2026-11-01)`）、`today = 2026-10-20`、时区 `Asia/Shanghai`；日期均按半开区间处理。端到端导航用例改用设备当前月份和注入的 `Clock`。
4. 金额单位为“分”，金额断言均为 `Long` 精确值。
5. JVM 数据由 `testing/RoomTestData` 构造：信封 A、B，预算 D1~D3，支出 B1~B7，未知信封使用 `envelopeId(0xEE)` 一类工厂生成。
6. Instrumented 数据由 `testing/InstrumentedTestData` 构造；Hilt 端到端用例使用 `TestDatabaseModule` 的内存数据库。
7. 执行方式：JVM 全量使用 `:app:testDebugUnitTest`（同时包含 `test` 与 `testDebug`）；instrumented 使用 `:app:connectedDebugAndroidTest`，需要真机或模拟器，当前共 36 条。

## 附：覆盖边界

1. 归档信封：`EnvelopeDao.observeSummaries` 仍返回归档行，以保留“归档交易计入总支出”的能力；`OverviewViewModel` 负责从列表隐藏归档信封，并在汇总预算中排除归档预算。对应用例为 `OverviewViewModelTest` 的两条。
2. 软删除：预算查询、信封汇总、分摊明细与按日汇总均排除 `deletedAt` 非空的行；对应用例分布在 `BudgetDaoTest`、`EnvelopeDaoTest`、`ExpenditureAllocationDaoTest` 及 instrumented 的 `EnvelopeSummaryQueryInstrumentedTest`。
3. 预算区间：`List<HalfOpenDateSpan>.hasOverlap()`、`BudgetDao.countOverlaps` 与 `insertEnvelope`/`insertBudget`/`updateBudget` 的 `BudgetWriteResult` 共同覆盖重叠拒绝；相邻区间不算重叠。
4. `ExpenditureSubmission` 不再接收手写的 `happenedDate`，由 `happenedAt` 和 `happenedZone` 推导；相关断言在 `MappersTest` 与 `RoomEnvelogRepositoryTest` 中。
5. 未覆盖：信封删除、按日/每 n 日预算、预算按权重分配、日期选择器交互、真实设备上的 39 条 instrumented 回归（本轮只验证了编译）。`OverviewViewModel` 之外的 ViewModel 仍无独立测试类。
