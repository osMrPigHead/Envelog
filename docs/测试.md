# 测试

## 一、测试口径

1. 测试对象以当前代码结构为准：源码分为 `core`（时间、金额、语言等基础能力）、`data`（Room 实体、DAO、查询模型、仓库）、`ui`（Compose）。测试只跟随这三层，不再引用重构前的 `data.repository_old`、`data.query_old`、`util.date`。
2. 单元测试只覆盖确定性逻辑：给定入参得到固定结果，不依赖系统时间、网络、设备状态。
3. 数据层测试不 mock：DAO 与仓库直接跑真实的 Room + SQLite 内存库，用断言固定 SQL 语义（统计窗口、归属月份、软删除、当前/历史拆分），不使用假实现模拟查询行为。
4. UI 层不写单元测试：Compose 组件的布局与交互留待手工验证；`ui/text` 与 `ui/component` 中依赖 `android.icu` 或 `stringResource` 的格式化逻辑不在单测范围内。
5. 一个用例只固定一个行为，命名使用 `被测方法_条件_期望`。
6. 时间相关测试的数据固定在 2026 年 10 月，`today` 固定为 2026-10-20，避免运行时刻影响结果。
7. 断言库保持 JUnit4（`org.junit.Assert`），协程测试用 `kotlinx-coroutines-test`；instrumented 测试用 `runBlocking`。
8. 测试不为了变绿而迁就缺陷：先判断是实现不符合预期还是需求变化，再决定改测试还是改实现。已知缺陷单独记录在第八节，不在测试里把错误行为固定成契约。
9. 当前统计：JVM 单元测试 75 个（`test` 72 个 + `testDebug` 3 个），instrumented 测试 4 个。

## 二、源根划分

```
app/src/test         JVM 单元测试：纯逻辑 + Robolectric 内存 Room
  java/cn/osmrpighead/envelog/
    core/time          DateSpanTest、TimeConversionTest
    core/number        NumberTest
    util               CollectionExtensionsTest、FlowExtensionsTest
    data/db/converter  ConvertersTest
    data/db/entity     EntityMappingTest
    data/db/dao        EnvelopeDaoTest（Robolectric）
    data/query         EnvelopeSummaryTest
    data/repository    RoomEnvelogRepositoryTest（Robolectric）
    testing            RoomTestData（测试夹具与内存库构造）
app/src/testDebug    debug 变体数据测试：DemoSeedDataTest
app/src/androidTest  真机/模拟器：EnvelopeSummaryQueryInstrumentedTest
```

1. `app/src/test` 是 JVM 单测的主源根，包路径与主源根一一对应；新增被测类时在相同包下建测试类。
2. 需要 Android 运行时的测试（Room、`Context`）放在 `app/src/test` 并用 Robolectric，不进 `androidTest`。
3. `app/src/testDebug` 只放依赖 debug 变体代码的测试，当前用于 `DemoSeedData`。
4. `app/src/androidTest` 只放"必须在真实 SQLite 上复验"的用例，避免与 Robolectric 用例重复堆叠。

## 四、关键用例设计

1. 汇总查询的统计窗口：某信封存在 `attributedMonth` 等于查询月份的预算时，统计窗口取该信封当月预算跨度的 `MIN(startDate)` 与 `MAX(endDate)`，且不窄于查询月份；不存在时窗口就是查询月份。边界按左闭右开处理，即 `>= start`、`< end`。
2. 归属月份只影响金额汇总：`totalBudget`、`priorBudget` 只累加 `attributedMonth` 等于查询月份的预算；`currentBudget` 只看 `today` 是否落在区间内，与归属月份无关。
3. 当前/历史拆分：`priorBudget` 只累加 `endDate <= today` 的预算；`priorAllocated` 的终点是当前预算的起点，没有当前预算时回退到 `today`。
4. 软删除：`deletedAt` 非空的预算与支出都不参与任何汇总，也不参与当前预算区间判定。
5. 仓库映射：`isBudgeted` 决定映射成 `Budgeted` 还是 `NonBudget`；预算行缺失时映射为 `totalBudget = 0`、区间为空、`usedProportion` 无效，而不是 `NonBudget`。
6. 归档：`archiveEnvelope` 用条件更新实现幂等，第一次返回 `Archived`，第二次返回 `NotFound`，`archivedAt` 不被覆盖。
7. 支出写入：`recordExpenditure` 的入参校验用 `require`，用例覆盖空分摊、日期与时间不一致、重复信封、非正金额、分摊指向其他支出、归档信封六种拒绝，并断言失败后汇总金额为 0（事务已回滚）。

## 五、运行方式

1. 全部 JVM 单测：`gradle :app:testDebugUnitTest`。仓库未提交 `gradlew` 脚本，可在 IDEA 的 Gradle 面板执行同名任务；Gradle 版本见 `gradle/wrapper/gradle-wrapper.properties`（9.7.1），JDK 使用 17。
2. 只跑一个类：`gradle :app:testDebugUnitTest --tests "cn.osmrpighead.envelog.data.db.dao.EnvelopeDaoTest"`。
3. 真机/模拟器：`gradle :app:connectedDebugAndroidTest`，需要已连接设备或已启动模拟器。
4. Robolectric 在 JDK 17 上最高只支持 SDK 35，因此两个 Robolectric 测试类用 `@Config(sdk = [35])` 固定沙箱版本；SDK 36 需要 JDK 21，切换 JDK 后可同时去掉该注解。
5. 首次运行 Robolectric 会下载 `android-all-instrumented`（约 190 MB）到 `~/.m2/repository`；离线机器需预置该文件，否则测试会在创建沙箱时报 `ConnectException`。
6. 内存紧张时用 `--max-workers=1` 运行，避免多个测试 JVM 并发导致 Gradle 守护进程被系统终止。

## 六、构建配置改动

1. `app/build.gradle.kts` 打开 `android.testOptions.unitTests.isIncludeAndroidResources = true`，Robolectric 需要合并后的资源与清单。

3. 新增 `androidTestImplementation("androidx.test:core:1.7.0")`，instrumented 测试通过 `ApplicationProvider` 取 `Context`。

## 八、已知缺陷与未覆盖项

1. `EnvelopeDao.observeEnvelopeSummariesOverlaps` 的 `FROM` 子句里多个 `LEFT JOIN` 没有 `ON` 条件，CTE 之间实际是笛卡尔积：信封数大于 1 或存在多条分摊/预算时会重复出行，且同一信封的 `allocated` 可能取到其他信封的值。现有汇总用例使用单信封数据，没有把这一现状固定成断言；该查询修复后应补多信封用例。
2. 汇总查询没有按 `archivedAt` 过滤，归档信封仍出现在 `observeOverview` 的结果中，与重构前"归档信封不进列表"的口径不一致，因此没有断言归档信封的可见性。
3. `recordExpenditure` 对不存在的信封没有显式校验，只靠外键约束失败；异常类型取决于 SQLite 驱动，未纳入断言。
4. 同一信封存在多个覆盖 `today` 的预算时，`currentBudget` 会产生多行并导致汇总重复，未覆盖。
5. 未覆盖对象：`OverviewViewModel`（需要 `Dispatchers.Main` 与 `AppStateHolder` 依赖链）及其私有的 `toSummaryItems` 汇总、`TodayProvider`（依赖 `ProcessLifecycleOwner` 与系统广播）、`Formatter`（`android.icu` 只在设备上可用）、`ui/component` 与 `ui/screen` 下的 Compose 组件、`core/navigation` 路由。
